## 3. 方案（两层）

### 第 1 层（必做）—— 公开托管 + §6 真实链接

- 将轻量工程（`03_code/`、`02_ai_chats/`、`05_results/` 的非权重部分）推送到公开仓库（GitHub/GitLab）。
- 仓库根目录补两份文件：
  - `README.md`：环境安装与运行方式（对应报告 §6.2）；
  - `MANIFEST.md`：把原附录的映射关系移入仓库，即"**证据 → 文件位置 → 证明什么**"三列（内容取自原 Appendix A/C，含 `02_ai_chats/I0_algorithm_search_chat.md`、`convnext_algorithm_profile.md`、`05_results/full_convnext_tiny_cifar10/`、`_failed_runs/...` 等条目）。
- 大文件（`*.pt`、结果 zip、原始数据）用 `.gitignore` 排除，改放 **GitHub Releases / Zenodo / HuggingFace**，并记录 **SHA-256** 供复现校验。

### 第 2 层（可选）—— 报告保持自足，但不新增附录

若希望评审者"不点链接也能评估"，把少量决定性证据**并入对应正文章节**即可，无需恢复附录：

| 证据 | 已在正文的位置 |

| 候选池与取舍标准 | §1.3 Table 2 |
| 算法来源与许可 | §1.4 Table 3 |
| 训练配置快照 | §4.2 Table 9 |
| 主结果 / 逐类指标 | §4.3 Table 10、§4.5 Table 11 |
| fp16 失败对照 | §4.6 Table 12 |
| 训练曲线、混淆矩阵等 | §4.4–§4.5 Figure 1–4 |
| 复现命令 | §6.2 |

> 说明：以上均已存在于正文，报告本身已具备自足性；**无需**再内联长段对话记录。

## 4. 推荐提交方式（按优先级）

| 优先级 | 方式 | 是否满足要求 |
|:---:|---|---|
| **1（首选）** | 报告 **PDF** + §6 真实仓库链接 | ✅ CON-5、CON-7 全满足 |
| **2（更稳）** | 在方式 1 基础上，另将 ~6 MB 轻量 ZIP 作为附件上传 UMMoodle | ✅ 且抗链接失效 |
| **3（平台限单文件时）** | 仅提交报告 PDF，靠 §6 链接承载全部支撑材料 | ✅ 前提是链接真实可用 |
| **4（须先确认）** | 邮件/共享盘提交完整归档 | ⚠️ 取决于教师，勿默认 |

**格式优先选 PDF**：固化版式、公式与图表，跨机器一致。

## 5. 风险与注意事项

1. **链接可达性** —— 报告 §6 已填入真实仓库链接；提交前请用**无痕窗口实测**可打开，关键链接可补 Zenodo DOI 或 `web.archive.org` 存档。
2. **仓库体积** —— GitHub 单文件 >100 MB 会被拒；务必排除 `.pt` 与原始数据，大文件走 Releases。
3. **Word / PDF 一致性** —— 二者必须同源；本次修改后已同步重导出 PDF（20 页）。
