# logs —— 日志

> 结果分类：**【日志】** ｜ 对应报告第 4 项「Experiment settings and results」的过程证据
> 全部日志由 `03_code` 在运行过程中自动写出，**带时间戳**，可用于核对执行阶段与耗时。

---

## 1. 日志清单

| 文件名 | 内容 | 产生阶段 | 写入方式 |
|---|---|---|---|
| `train.log` | 完整训练日志：环境与设备信息、数据划分、显存/batch size 决策、模型结构摘要与参数量、逐轮训练与验证指标、最优模型保存、测试集评估、逐类准确率、总耗时 | **训练阶段**（`train.py`） | `src/utils/logger.py`，控制台+文件双写，追加模式 |
| `evaluate.log` | 独立评估日志：检查点加载、模型配置恢复、测试集指标、逐类准确率 | **评估阶段**（`evaluate.py`） | 同上 |
| `history.json` | 逐轮结构化指标：`epoch / train_loss / train_acc / val_loss / val_acc / lr / epoch_time` | **训练阶段**，训练结束时写出 | `json`（供绘图与报告引用） |
| `history.csv` | 与 `history.json` 同源，但为 **CSV 表格形式**（一行一轮，准确率已换算为百分数，学习率为科学计数法） | **训练阶段**，由 `src/utils/csv_logger.py::write_history_csv()` 生成 | 可直接作为报告中的"逐轮指标表" |

## 2. 日志中的执行阶段（`train.log`）

日志按固定的阶段顺序输出，每一行都带 `[HH:MM:SS]` 时间戳，便于标注执行阶段：

| 阶段 | 日志特征串 | 说明 |
|---|---|---|
| 1. 环境初始化 | `实验名称` / `输出目录` | 打印实验名与产物落盘位置，并写出 `config.json` |
| 2. 设备与种子 | `[device]` / `[seed]` | 计算设备（CUDA/MPS/CPU）与全局随机种子、确定性开关 |
| 3. batch size 自适应 | `[batch-size]` | 显存探测过程：期望值、试探候选、是否下调/上调、探针峰值显存；**CPU 上会直接说明无显存限制** |
| 4. 数据准备 | `[data]` | 划分规模、DataLoader 配置；若使用快速验证子集，会输出醒目的 `WARNING` |
| 5. 数据样例 | `[figures]` | 数据样例图保存路径 |
| 6. 模型构建 | `[model]` | ConvNeXt 各阶段分辨率/通道数/Block 数、总参数量与可训练参数量 |
| 7. 训练循环 | `[Epoch i/N]` + `epoch i | step s/S` | 每轮起始学习率；每 50 个 step 打印一次 batch 级 loss/acc/lr；轮末汇总 train/val 指标与耗时 |
| 8. 最优模型 | `-> 刷新最优验证准确率` | 验证准确率创新高时保存 `best.pt` |
| 9. 训练结束 | `训练结束` | 历史最优验证准确率、对应轮次、曲线保存路径 |
| 10. 测试评估 | `[evaluate]` / `[test]` | 载入 `best.pt`，输出测试集 loss / Top-1 / Top-5 |
| 11. 逐类分析 | `逐类准确率（测试集）` | 每类准确率与支撑样本数、宏平均 |
| 12. 收尾 | `全部完成` | 总耗时、最终 Top-1、结果与图表目录 |

## 4. 与其它部分的关系

| 关联 | 说明 |
|---|---|
| 日志 ← 代码 | 日志由 `03_code/src/utils/logger.py` 生成，格式固定、阶段可追溯 |
| 日志 ← 数据 | `[data]` 行记录了实际读取的数据目录规模与划分，可与 `../../../04_data/splits/split_info.json` 交叉核对 |
| 日志 → 图表 | `history.json` 是 `../figures/training_curves.png` 的数据来源 |
| 日志 → 指标 | 测试指标与 `../metrics/test_metrics.json` 一致；日志是"何时得到该指标"的时间证据 |
| 日志 → 模型 | `-> 刷新最优验证准确率` 行对应 `../models/best.pt` 的保存时刻 |
