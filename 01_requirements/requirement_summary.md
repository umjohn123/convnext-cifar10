## 2. 任务性质（摘自作业正文）

本次作业的本质**不是**"写代码解决一个 CV 问题"，而是：

> 设计并记录一条**由 AI 驱动、可复现**的"算法检索 → 实现 → 验证 → 成文"流水线，并以报告形式呈现该过程。

作业明文要求：

1. 必须借助 **AI 工具（如 Deepseek、ChatGPT）或 AI Agent** 完成**全部**工作，
   包括但不限于：算法检索、程序设计，**乃至报告撰写**；
2. **不允许自己编写任何代码**（You are NOT allowed to write any code by yourself）；
3. 通过 **UMMoodle** 在线提交报告。

## 6. 交付与提交要求

| 项目 | 要求 |
|---|---|
| 提交平台 | UMMoodle |
| 唯一必交项 | **英文报告**（Word 或 PDF） |
| 报告中须内嵌 | 源代码的**可访问网页链接**（报告第 6 项） |
| 支撑性过程材料 | AI 对话记录、代码工程、数据集说明、实验结果、图表（**内部归档**，不随 UMMoodle 提交） |

### 6.1 提交物与内部归档的区分（重要）

- **提交物（UMMoodle）**：只有 **英文报告（Word 或 PDF）** 一项；报告中必须内嵌**源代码的可访问网页链接**（报告第 6 项）。
- **内部归档**：`01_requirements/`～`06_report/` 六个目录是**项目内部的材料组织方式**，用于留存过程证据、支撑报告撰写与自查；**除报告本身外，均不随 UMMoodle 提交**。
- 因此，本文档及关联文档中凡出现 ``02_ai_chats/``、``03_code/``、``04_data/``、``05_results/``、``06_report/`` 等路径，均应理解为**内部归档位置**，而非"需要单独上传的交付物"。

### 6.2 `02_ai_chats/` 的处理规范

`02_ai_chats/` 存放"由 AI 完成全部工作"（CON-4）的**过程证据**：算法检索对话记录（`*.md`）、迭代小结与算法档案。其处理方式如下：

| 事项 | 规范 |
|---|---|
| 是否提交 | **不单独提交**。UMMoodle 只收报告；该目录属内部归档 |
| 是否保留 | **必须保留**。CON-4 / AC-4 要求提供 AI 对话记录作为过程证据，删除即失去可核验性 |
| 如何对外可达 | 随 `03_code/` 一并**发布到报告 §6 的源码仓库**（把 `02_ai_chats/` 作为仓库子目录），使证据通过报告内链接即可核验 |
| 是否写入报告正文 | **不整段复制**。报告内以概述或少量摘录引用即可 |
### 6.3 同类引用问题的排查方法

凡以 ``<编号>_<名称>/`` 形式出现的目录路径，都可能是同一类问题（把**内部归档**误当成**提交交付物**）。排查步骤如下：

1. **扫描**：全文检索形如 ``\d\d_[a-z_]+/`` 的路径引用（如 ``02_ai_chats/``、``03_code/``、``04_data/``、``05_results/``、``06_report/``）。
2. **分类**：逐条判定语义——是"提交给 UMMoodle 的交付物"，还是"内部归档位置 / 报告素材来源"。前者**只有报告一项**。
3. **改写**：把"交付物 / DEL-x"一类措辞改为"内部归档 / 过程证据"，或在同句补注"（内部归档，不随 UMMoodle 提交）"。
4. **校验一致性**：确认全文"唯一必交项"的表述与本表一致，且报告 §6 的链接是这些内部材料**唯一的对外可达入口**。
5. **回归**：目录结构每次调整后重跑步骤 1–4（可并入 T10 的提交前检查清单）。
