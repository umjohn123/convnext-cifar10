## 第 1 轮：约束条件的确认与转写

**提问要点**
> 我需要完成一份「用 AI 完成全部工作」的作业，要求选定一个**近期算法**用于**计算机视觉与模式识别**。
> 请先把作业里的硬性限定逐条提取出来，形成可以逐条核验的清单，便于我在后续检索时排除不合规的算法。

**AI 回答要点**
1. 算法类别限定为 **Deep CNN** 或 **Deep Autoencoder**（二者之一，纯 Transformer 视觉模型不合规）；
2. 提出年份限定为 **2022–2026**，且必须能提供可核验的来源（论文或官方实现）；
3. 应用领域必须是 **CV / PR**（分类、检测、分割、重建等）；
4. 全部代码须由 AI 生成，人类不得手写；
5. 报告须为英文 Word/PDF，且必须给出源码的可访问网页链接。

**结论 / 落盘产物**
- 形成后续检索的三条硬筛选线：`类别 ∈ {Deep CNN, Deep Autoencoder}`、`年份 ∈ [2022, 2026]`、`领域 = CV/PR`。
- 落盘：本记录（`02_ai_chats/I0_algorithm_search_chat.md`）。

## 第 2 轮：候选算法的发散检索

**提问要点**
> 请按上述三条硬筛选线，给出 **2022–2026 年间提出**、属于 Deep CNN 或 Deep Autoencoder、
> 且应用于 CV/PR 的候选算法清单。每个候选请给出：论文标题、发表会议/期刊与年份、
> 核心贡献一句话、以及**在有限算力（CPU 或 Colab 免费 GPU）下的可实施性**评价。

**AI 回答要点（候选池）**

| 候选 | 年份 | 类别 | CV 应用 | 有限算力可实施性 |
|---|---|---|---|---|
| **ConvNeXt**（A ConvNet for the 2020s） | 2022 | Deep CNN | 图像分类/检测/分割 | 高：纯 PyTorch 实现，无自定义 CUDA 扩展，官方 `timm`/`torchvision` 均收录 |
| **ConvNeXt V2** | 2023 | Deep CNN + 自编码预训练（FCMAE） | 图像分类 | 中：需自监督预训练阶段，训练成本更高 |
| **Masked Autoencoders (MAE)** | 2022 | Deep Autoencoder | 自监督表示学习 / 分类 | 中低：属自编码器类别，但预训练算力需求较高 |

**结论 / 落盘产物**
- 候选池成型，落盘：`02_ai_chats/algorithm_candidates.md`。

## 第 3 轮：按「算力可承受度 + 实现清晰度 + 类别合规性」收敛选型

**提问要点**
> 请以上述三个候选为例，按「**算力可承受度 + 实现清晰度 + 类别合规性**」三个维度做优先级排序，
> 并说明为什么推荐其中的某一个作为主算法。请特别说明它在**小分辨率数据集（如 CIFAR-10）**上的适配代价。

**AI 回答要点**
1. **类别合规性**：三者都合规；但 ConvNeXt 与 ConvNeXt V2 是**纯 Deep CNN**，最贴合"Deep CNN"限定，
   而 MAE 属自编码器路线、预训练成本高，不适合作为首个可交付实验。
2. **实现清晰度**：ConvNeXt 的模块边界非常清晰（Stem → 4 阶段 → 分类头），
   关键设计（倒置瓶颈、7×7 深度卷积、LayerNorm 替代 BatchNorm、独立下采样层）都能独立实现与验证，
   便于报告第 2 项"算法描述"逐条对照。
3. **算力可承受度**：ConvNeXt 可在 CPU 上以缩小规模跑通 MVP，在 Colab 免费 GPU 上可完成全量实验；
   ConvNeXt V2 额外需要 FCMAE 预训练，成本翻倍。
4. **小分辨率适配**：论文 Stem 为 4×4、stride=4（适配 224×224）；CIFAR-10 仅 32×32，
   若沿用 stride=4 会使特征图迅速缩到 8→4→2→1、空间信息损失过大。
   **建议改用 3×3、stride=1 的卷积式 Stem**，四阶段分辨率变为 32→16→8→4，
   保留论文全部关键模块的同时适配小分辨率输入。

**结论 / 落盘产物**
- **选定 ConvNeXt 作为主算法**。
- 落盘：算法档案 `02_ai_chats/convnext_algorithm_profile.md`。

## 第 5 轮：确定实验范围与数据适配

**提问要点**
> 请给出 ConvNeXt 的最小可实施实验方案：适配的数据集、输入分辨率、模型规模选择、
> 以及在**无 GPU 的 CPU 环境**下如何先跑通端到端流程。

**AI 回答要点**
1. **数据集**：CIFAR-10（32×32 RGB，10 类，60000 张），规模适中、下载校验完备、CPU 可跑；
2. **模型规模**：提供多档预设（atto/femto/pico/nano/tiny），
   其中 `tiny` 对应论文 ConvNeXt-T 的原始配置（(3,3,9,3) / (96,192,384,768)，约 27.8 M 参数），
   小档位用于 CPU 快速验证；
3. **CPU 策略**：先用"**快速验证子集 + 少量轮次 + 较小模型**"跑通全链路（对应迭代 I0），
   再在 GPU/Colab 上以全量数据和完整轮次复跑（对应迭代 I1）；
4. **增强与正则**：沿用论文训练配方（RandomCrop/HFlip/RandomErasing、标签平滑、Mixup/CutMix、
   warmup + cosine、AdamW 且对 1 维参数豁免权重衰减）。

**结论 / 落盘产物**
- 实验范围确定：CIFAR-10 + ConvNeXt（多档规模可切换）+ CPU 小规模先行的两阶段策略。
- 落盘：`02_ai_chats/ai_collaboration_plan.md`（迭代计划）、本记录第 5 轮。
